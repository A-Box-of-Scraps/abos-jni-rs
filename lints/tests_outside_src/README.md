# Tests outside src

`tests_outside_src` keeps test implementations outside each package's `src/` directory. Production source can
declare a path-included child module to retain access to private members:

```rust
#[cfg(test)]
#[path = "../tests/unit/mod.rs"]
mod tests;
```

When placing path-included test modules under `tests/`, use a subdirectory such as `tests/unit/`, rather than placing
them directly in `tests/`, so Cargo does not also compile them as standalone integration tests. This is a Cargo layout
consideration, not a requirement to use `tests/`; a path such as `../ui/unit.rs` also keeps the implementation outside
`src/`.

## Rules

Inside a package's `src/`, the lint rejects:

- `#[test]` and qualified attributes ending in `::test`.
- Test-only code gated by `#[cfg(test)]`, including inline modules, helpers, constants, and macro invocations.
- Compound test-only predicates such as `#[cfg(all(test, windows))]`.
- Test attributes introduced through `#[cfg_attr(...)]`.

Out-of-line module declarations with a direct `#[path]` resolving outside the package's `src/` are allowed. Source
locations and resolved paths are checked, not module names. The nearest ancestor `Cargo.toml` defines the package
boundary. Documentation examples, `#[cfg(not(test))]`, code shared with production through `#[cfg(any(test, ...))]`, and
files outside `src/` are not rejected.

This is a pre-expansion lint: it sees inactive branches in files the compiler parses, but cannot inspect files that the
compiler never loads (for example, a Windows-only external module on Linux), nor tests generated by macro expansion. Run
the lint for the supported targets/features for broader coverage. It is not a filesystem-wide scanner.

## Development

This crate belongs to the shared `lints/` workspace. The workspace owns the pinned nightly toolchain, Dylint dependency
versions, and lockfile.

```sh
mise run test:lints
mise run lint
```

The root lint task loads all lint libraries and treats warnings as errors. UI fixtures under `ui/` intentionally contain
a miniature package with both accepted test layouts and rejected `src/` implementations; `.stderr` snapshots record
expected diagnostics.
